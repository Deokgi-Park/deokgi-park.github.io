# npm 프록시 설정 가이드

사내망이나 VPN 환경에서 `npm install`을 실행하면 패키지를 아예 받아오지 못하고 타임아웃이 나는 경우가 있습니다. 이는 npm이 외부 레지스트리(registry.npmjs.org)에 직접 접근하려고 하는데, 네트워크 경로상의 프록시 서버를 거치지 않아 요청이 막히기 때문입니다. 이 문서에서는 이런 상황에서 npm이 프록시를 통해 통신하도록 설정하고, 확인하고, 다시 해제하는 방법을 정리합니다.

---

## 1) 프록시 서버와 VPN이란?

본격적인 설정에 앞서 두 개념을 짚고 넘어갑니다.

**프록시 서버(Proxy Server)**는 내 컴퓨터와 인터넷 사이에서 요청을 대신 중계해주는 서버입니다. 원래는 `내 PC → 인터넷`으로 바로 연결되어야 할 요청이, 프록시가 있는 환경에서는 `내 PC → 프록시 서버 → 인터넷` 순서로 흘러갑니다. 회사에서는 보통 다음과 같은 이유로 프록시를 강제합니다.

- 내부 네트워크에서 나가는 트래픽을 한곳에서 감시·통제하기 위해
- 접근 가능한 사이트를 제한하기 위해
- 외부 요청 결과를 캐싱해 트래픽을 줄이기 위해

문제는 npm, git, curl 같은 도구들은 시스템(브라우저)의 프록시 설정을 자동으로 따라가지 않는다는 점입니다. 각 도구마다 "이 프록시를 거쳐서 나가라"고 별도로 알려줘야 하며, 이 문서에서 다루는 `npm config set proxy` 설정이 바로 그 역할입니다.

**VPN(Virtual Private Network)**은 인터넷처럼 개방된 네트워크 위에 암호화된 전용 통로를 만들어, 마치 회사 내부망에 물리적으로 연결되어 있는 것처럼 만들어주는 기술입니다. 재택근무 중에 VPN을 켜면 내 PC의 네트워크 트래픽이 회사 내부망을 거쳐 나가도록 우회되는데, 이때 회사 내부망에 설정된 프록시 정책까지 그대로 적용되는 경우가 많습니다. 즉, VPN 연결 자체가 프록시를 강제하는 것은 아니지만, "VPN 연결 = 사내망 진입 = 사내 프록시 정책 적용"으로 이어지는 경우가 흔해서 이 문서 제목에도 VPN을 함께 언급했습니다.

정리하면, 아래 순서로 문제가 발생합니다.

1. VPN을 켜거나 사내망에 접속한다
2. 사내 네트워크 정책상 외부 요청은 프록시 서버를 반드시 거쳐야 한다
3. npm은 이 정책을 모르고 그냥 인터넷에 직접 나가려다 막힌다
4. npm에게 "프록시를 거쳐 나가라"고 알려줘야 한다 → 이 문서의 본론

## 2) 프록시 설정하는 법

아래 예시는 프록시 서버 주소가 `192.168.49.1`, 포트가 `8282`인 경우입니다. 실제 값은 사내 IT 부서나 VPN 안내 문서에서 확인한 프록시 주소로 바꿔서 사용하면 됩니다.

```powershell
npm config set proxy http://192.168.49.1:8282
npm config set https-proxy http://192.168.49.1:8282
npm config set noproxy localhost,127.0.0.1
```

각 줄이 하는 일은 다음과 같습니다.

- `proxy` : `http://` 로 시작하는 요청을 어떤 프록시로 보낼지 지정
- `https-proxy` : `https://` 로 시작하는 요청(대부분의 npm 레지스트리 통신)을 어떤 프록시로 보낼지 지정
- `noproxy` : 여기 나열된 주소로 가는 요청은 프록시를 거치지 않고 직접 접속(로컬 개발 서버 등)

프록시 서버에 아이디/비밀번호 인증이 필요한 경우에는 URL 안에 인증 정보를 포함해서 설정합니다.

```powershell
npm config set proxy http://USER:PASS@PROXY_HOST:PORT
npm config set https-proxy http://USER:PASS@PROXY_HOST:PORT
```

> 비밀번호에 `@`, `:`, `/` 같은 특수문자가 들어있다면 URL 인코딩이 필요할 수 있습니다.

---

## 3) 현재 설정 확인하는 법

설정이 제대로 반영됐는지는 다음 명령으로 확인합니다.

```powershell
npm config get proxy
npm config get https-proxy
npm config get noproxy
```

전체 설정 목록에서 프록시 관련 항목만 눈으로 훑어보고 싶다면 아래처럼 전체 목록을 출력한 뒤 찾아봅니다.

```powershell
npm config list -l
```

설정이 실제로 동작하는지는 레지스트리에 핑을 날려서 확인할 수 있습니다.

```powershell
npm ping
```

이 명령이 정상 응답을 받으면 프록시를 통해 npm 레지스트리까지 통신이 되고 있다는 뜻입니다.

---

## 4) 프록시 삭제(해제)하는 법

VPN을 끄거나 사내망을 벗어나 일반 인터넷 환경으로 돌아왔다면, 설정해뒀던 프록시를 그대로 두지 말고 삭제하는 것을 권장합니다. 일반 인터넷 환경에서 사내 프록시 주소가 남아있으면 오히려 그 프록시 서버에 접속할 수 없어서 npm이 먹통이 됩니다.

```powershell
npm config delete proxy
npm config delete https-proxy
npm config delete noproxy
```

삭제 후 아래 명령을 실행했을 때 결과가 `null`로 나오면 해제가 정상적으로 완료된 상태입니다.

```powershell
npm config get proxy
npm config get https-proxy
```

---

## 5) 언제 설정하고 언제 지울까

정리하면 판단 기준은 단순합니다.

- **VPN 연결 중 / 사내망 접속 중** → 프록시 설정 (2번 항목)
- **VPN 해제 / 일반 인터넷 환경으로 복귀** → 프록시 삭제 (4번 항목)

이렇게 네트워크 환경이 바뀔 때마다 프록시 설정 여부를 함께 전환해주면, "분명 어제는 됐는데 오늘은 npm install이 안 된다"는 상황의 상당수를 예방할 수 있습니다.
